# Nagare v0.1 execution plan

This plan turns the v0.1 roadmap into reviewable, issue-sized changes. Each
task has one numerical contract and one independently runnable validation gate.
Tasks are ordered by dependency; a later task does not start until every gate
of its prerequisites passes.

## Numerical contracts

### Knot sequence

- A knot sequence contains at least two finite `Float64` values.
- Knots are strictly increasing. Duplicate or descending knots are errors.
- Ordinates have the same length as knots and are finite.
- Construction validates the table. Because Mojo 1.0 allows callers to mutate
  underscore-prefixed fields, every public table observation revalidates
  length, finiteness, and strict ordering before indexing stored data.

### Interval location

- An interval is identified by its left index `i` and denotes
  `[knots[i], knots[i + 1]]`.
- The result is always in `0 .. len(knots) - 2`.
- Interior knots are right-biased: querying `knots[i]` returns `i`.
- The final knot is assigned to the final interval.
- The public locator accepts only finite, in-domain queries. Out-of-domain and
  non-finite queries raise an error.
- Standalone lookup performs `O(n)` validation followed by `O(log n)` binary
  search.

### Linear interpolation

For the selected interval, evaluation uses

```text
y(x) = y[i] + (x - x[i]) * (y[i + 1] - y[i]) / (x[i + 1] - x[i])
```

- Every knot value is reproduced exactly by an explicit knot fast path.
- Well-conditioned in-domain affine data is reproduced to normal `Float64`
  rounding error.
- Finite in-domain evaluation chooses direct-delta or scale-normalized affine
  arithmetic according to intermediate representability: an avoidable
  overflow must not turn a result inside the finite endpoint range into
  infinity or NaN.
- Extrapolation is explicit and nominal:
  - `ERROR` (default) rejects an out-of-domain query;
  - `CLAMP` returns the nearest endpoint ordinate;
  - `LINEAR` extends the first or final segment.
- `LINEAR` returns IEEE signed infinity when the represented extrapolated line
  exceeds the finite `Float64` range. Finite inputs do not produce NaN.
- Non-finite queries always raise, regardless of extrapolation policy.
- For intervals spanning nearly the entire finite `Float64` range, coordinate
  normalization prevents intermediate overflow but can erase a central offset
  smaller than one ULP of the normalized interval. Evaluation remains finite
  and inside the endpoint hull for an in-domain query, but exact affine
  recovery is not promised for that ill-conditioned case.

### Cubic spline (v0.1 target)

- The first spline is a one-dimensional, natural cubic spline over the same
  validated knot contract.
- The interpolant passes through all knots and has continuous first and second
  derivatives at interior knots.
- Natural boundary conditions set the endpoint second derivatives to zero.
- It reuses the same three extrapolation policies; no hidden boundary behavior
  is introduced by a spline implementation.

### Comparison tolerances

- Knot reproduction, clamp results, indices, and values representable exactly
  in binary use exact equality.
- The committed linear reference and affine-property fixtures use absolute
  error `<= 1e-12`; their expected magnitudes remain below 32.
- Each future cubic fixture must state absolute and relative tolerances before
  implementation. The comparison is
  `abs(actual - expected) <= max(atol, rtol * abs(expected))`.
- A tolerance is never widened merely to make a failing fixture pass. Changes
  require a numerical explanation and a regression case.

## Issue-sized tasks

### NAG-001 — Repository contracts and reference policy

Deliverables:

- this execution plan;
- documented knot, interval, extrapolation, and tolerance contracts;
- explicit v0.1 non-goals and validation gates.

Gate: documentation review confirms every public behavior has one owner and no
v0.2 algorithm is implied by the root API.

### NAG-002 — Validated interval location

Depends on: NAG-001.

Deliverables:

- finite, minimum-length, strictly increasing knot validation;
- deterministic right-biased binary search;
- public `locate_interval` export;
- boundary, invalid-input, and search-invariant tests.

Gate: unit tests cover first/final knots, every interior knot, values inside
every interval, and each rejection path. Package precompilation uses `--Werror`.

### NAG-003 — Linear interpolant and extrapolation policy

Depends on: NAG-002.

Deliverables:

- nominal `ExtrapolationPolicy` values;
- owning `LinearInterpolator` with construction and observation-time table
  validation;
- `evaluate` with exact-knot behavior and all three policies;
- a public example using only root imports.

Gate: exact fixtures, independently calculated reference values, affine
reproduction, segment-bounds invariants, and error-contract tests pass.

### NAG-004 — Linear interpolation benchmark baseline

Depends on: NAG-003.

Deliverables:

- construction and evaluation benchmarks for small, medium, and large knot
  tables;
- methodology recording CPU, OS, Mojo version, build flags, warmup, sample
  count, and statistic;
- no comparative performance claim.

Gate: benchmark output is deterministic in shape and clearly separates
validation/construction cost from repeated evaluation cost.

### NAG-005 — Natural cubic coefficient construction

Depends on: NAG-003.

Deliverables:

- tridiagonal coefficient solve in pure Mojo;
- stored per-interval cubic coefficients;
- explicit natural endpoint conditions;
- failure reporting for invalid or numerically unusable inputs.

Gate: known polynomial/reference fixtures and coefficient residual checks pass.

### NAG-006 — Cubic evaluation and continuity

Depends on: NAG-005.

Deliverables:

- scalar evaluation using NAG-002 interval search;
- first- and second-derivative evaluation required to test the contract;
- all extrapolation policies applied consistently.

Gate: knot passage, C0/C1/C2 continuity, natural boundary, constant/linear
reproduction, and reference-value tests pass within documented tolerances.

### NAG-007 — Package and downstream proof

Depends on: NAG-004 and NAG-006.

Deliverables:

- installed-package smoke tests for all root exports;
- Linux x86-64, Linux ARM64, and macOS ARM64 CI evidence;
- one minimal downstream consumer fixture;
- compatibility and changelog updates.

Gate: `pixi run check`, local package build, installed-package smoke test, and
the supported CI matrix all pass from a clean checkout.

## Validation gates

Every implementation task must pass these gates in order:

1. **Focused:** the directly affected TestSuite file passes.
2. **Numerical:** exact/reference/property tests for the changed contract pass.
3. **Style:** `pixi run format-check` passes without modifying files.
4. **Package:** `pixi run precompile` passes with warnings as errors.
5. **Repository:** `pixi run check` passes from the locked Pixi environment.
6. **Distribution:** at release boundaries, build the Conda package and test
   imports against the installed artifact rather than the source tree.

Reference fixtures must be independently calculated, committed as small exact
tables, and explained in the test or data-provenance document. Randomized tests
must use deterministic generated sequences and report the failing case.

## Non-goals for v0.1

- PCHIP, Akima, B-splines, smoothing splines, polynomial interpolation, and
  multidimensional interpolation;
- automatic sorting, duplicate-knot merging, missing-value imputation, or
  silent filtering of non-finite data;
- vectorized/SIMD/GPU kernels or a Nagare-specific array type;
- optimization, plotting, dataframes, signal processing, file I/O, or unit
  conversion;
- Python, C, or Rust runtime dependencies;
- API or ABI stability before the first useful release.
